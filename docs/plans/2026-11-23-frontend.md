## Architecture

Use Vite in SPA mode with React Router route modules loaded on navigation, TypeScript strict across application and tests, and one TanStack Query provider. The public routes cover login, registration, verification, forgot password, and reset. Protected routes cover dashboard, transactions, categories, and profile. The reports feature supplies dashboard report panels. Its data and presentation remain in reports without putting account data into a second store.

Generated `paths` and schemas are committed and regenerated from `docs/openapi.json`. The transport uses the typed operations with `credentials: 'include'` against relative `/api/v1` URLs. One error parser handles runtime bodies. The query cache holds server data, URL search parameters hold filters, sort, month and paging, and React Hook Form owns input and errors. Local React state handles transient UI only. Compose shadcn primitives with children and ordinary routes. Derive display values from query data and memoize chart transforms at the dashboard boundary. Load the chart code with the dashboard route.

The plan leaves existing backend endpoints, fields, storage, auth and behavior intact. If a missing API capability appears, pause for approval with the screen, the reason the current API cannot serve it, and a complete proposed contract. Approved additive work is separate and follows the repository's API test, migration, documentation, regenerated client and `feat(api)`/`fix(api)` commit process.

## API coverage

All paths below are relative to `/api/v1`. Use the trailing slashes on collection endpoints. Google OAuth and account deletion are outside scope. Balance Trend (`GET /reports/balance-trend`) stays available to the API and is outside the requested dashboard.

| Feature or action | Endpoint and input | Runtime response and UI behavior |
|---|---|---|
| Register | `POST /auth/register` with `email`, `username`, `password`, `confirm_password` | `201`, auth cookies and token JSON. Discard the success body. Refresh session query, show unverified status and resend action. Map field and account-conflict errors. |
| Login and bootstrap | `POST /auth/login` with `email`, `password`; `GET /auth/me` | `200` login sets cookies. Discard token JSON. `/auth/me` returns `id`, `email`, `username`, `is_active`, `is_verified`, `created_at`. Keep public login `401` outside session refresh. |
| Refresh | `POST /auth/refresh`, empty body and refresh cookie | `200`, rotated cookies, discard token JSON. Missing cookie `400`. Invalid or reused token `401`, cookies cleared. Refresh failure clears frontend account state. |
| Log out | `POST /auth/logout`, cookie | `200` message, cookies cleared and all sessions revoked. On success clear account query data and go to login. Preserve a retry action for a network/server failure. |
| Verify and resend | Explicit `GET /auth/verify-email?token=…`; authenticated `POST /auth/resend-verification` | `200` messages. Verify consumes the token and is never prefetched or retried automatically. A bad token gets a link error. Resend uses active signed-in user and handles `429`. |
| Forgot and reset | `POST /auth/forgot-password` with `email`; `POST /auth/reset-password` with `token`, `new_password`, `confirm_new_password` | `200` messages. Forgot is deliberately generic. Reset revokes the subject's sessions. Show success and a login action. |
| Monthly summary | `GET /reports/monthly-summary?year=…&month=…` | `200` with year, month, and decimal strings `income`, `expense`, `balance`. Show zeros and an explicit empty report state where applicable. |
| Category reports | `GET /reports/category-breakdown` with inclusive `date_from`, `date_to`, and `type` | `200` with category ID/name, optional color/icon, decimal `total`, count and numeric percentage. Show income or expense for the selected month, and retain `Uncategorized` for null IDs. |
| Recent activity | `GET /transactions/?page=1&per_page=5&sort_by=created_at&sort_order=desc` | `200` paginated transaction payload. Display nullable description/category gracefully. |
| Transactions list and filters | `GET /transactions/` with `page`, `per_page`, `date_from`, `date_to`, `category_id`, `type`, `min_amount`, `max_amount`, `search`, `sort_by`, `sort_order` | `200` with `items`, `total`, `page`, `per_page`, `pages`, `has_next`, `has_prev`. Search covers descriptions. Keep filters shareable and back/forward navigation functional. |
| Transaction details and CRUD | `GET /transactions/{id}`; `POST /transactions/` with `amount`, `description`, `transaction_date`, `category_id`, `type` and optional `notes`, `tags`; `PATCH` and `DELETE /transactions/{id}` | Detail `200` may include nullable nested category. Create `201` and edit `200` return a transaction. Patch changed fields only, with explicit null permitted for category and notes. Delete `204`, no body. Invalidate transaction and report queries after success. |
| Categories list and CRUD | `GET /categories/?page=…&per_page=100`; `GET /categories/{id}`; `POST /categories/` with `name`, `type` and optional `description`, `icon`, `color`; `PATCH` and `DELETE /categories/{id}` | List `200` is an array. Detail/edit `200`, create `201`, delete `204`. `user_id: null` marks a read-only system category. On delete conflict, provide compatible reassignment using `reassign_to_id`. |
| Profile read and update | `GET /users/me`; `PATCH /users/me` with changed `email` and/or `username` | `200` full normalized user object. Username-only update stays signed in. A different normalized email returns `is_verified: false`, revokes sessions, and queues no email. Send to login with the new email and offer resend after sign-in. |
| Change password | `POST /auth/change-password` with `current_password`, `new_password`, `confirm_new_password` | `200` message, cookies cleared and sessions revoked. Clear account state and prompt login. Map validation and invalid credentials to the form. |
| Deployment smoke | Public `GET /health/live` and `/health/ready` | Liveness `200` and readiness `200` or `503`, with the distinct readiness body. Use `/healthz` on nginx for frontend container health. |

### Transport and session invariants

- Discard successful token-bearing response streams without parsing them. Send no `Authorization` header and keep tokens out of storage, state, telemetry, and console output. Parse a `204` as empty. Remove email-link token query parameters from the browser address after capturing them in route memory, and leave those URLs out of request logs and referrers. On a reload after scrubbing, ask to reopen the email link.
- Convert the runtime `{detail, code, request_id, errors}` variants into one typed error: status, code, message, field issues, request ID, retry timing. Handle plain-detail, missing or invalid JSON, aborts, and network failures. Use `X-Correlation-ID` where supplied. Render `429` with a manual retry and a wait hint when available. For overload `503` with a valid `Retry-After`, show a waiting message and allow one cancellable retry after the specified delay on safe GETs only. An excessive delay leaves a manual retry action. Disable generic Query retry so policies cannot multiply. The verification GET and all mutations are manual on overload, network failures, and after auth recovery.
- A protected `401` joins one in-tab refresh promise. A response that arrives after a successful refresh for the same request generation uses that outcome so staggered `401`s cannot start another rotation. With `navigator.locks` available, one helper acquires a same-origin lock and calls `/auth/me` inside the lock with recursion and automatic retries disabled. A `200` means the browser already has valid cookies. Only a `401` proceeds to the cookie refresh. No tab broadcasts or persisted coordination. Without Web Locks, retain in-tab single-flight and document the multi-tab limitation. One test specifically covers the lock/recheck. Separate transport tests cover concurrent and staggered `401`s.
- After recovery, only an eligible GET replays once. Keep write input and offer explicit resubmission. Exclude refresh, public auth paths, verification, and the lock recheck from interceptor recursion. Any definitive refresh failure or second protected `401` clears private query data and returns to login. Account transitions cancel or ignore stale in-flight responses. Use the server's cookie and origin checks. Proxy `Host` unchanged in dev and production.

### Financial and visual invariants

- Preserve API decimal strings through validation, requests, cache and display. Validate positive transaction amounts using up to ten whole digits and two fractional digits. Validate filter positivity and ordering without imposing the transaction amount schema on the API's range filters. Use string normalization or integer units for comparisons. Format via `Intl.NumberFormat` with exact decimal input or `BigInt` whole/minor-unit formatting so localization and currency display preserve the stored amounts. Use `VITE_CURRENCY` only for formatting an optional ISO currency code, with no symbol by default and a clear configuration error for an invalid value. Keep two fractional places for monetary amounts. Convert to numbers only at the chart plotting boundary, and use the original strings for labels and summaries.
- Harbor Ink in light and dark, self-hosted Barlow Condensed and Instrument Sans, and the Ledger SVG. Use mobile-first navigation, focus order and visible rings, signed/labeled income and expense, inline form errors and live status, and an accessible data alternative to charts. Preserve 4.5:1 for text and 3:1 for focus on canvas and solid surfaces. Verify glass contrast and appearance in the browser with content behind the overlay. Use CSS translucency and `backdrop-filter` on nav, sheets, modals and toasts, with an opaque `@supports` fallback and reduced-transparency/forced-colors behavior. Tables, cards and charts stay solid. Respect reduced motion on status icon animation.

## Unresolved risks and decisions

- **Lock and supply chain** — The minimatch override awaits explicit approval and actual shadcn CLI verification. Re-resolve and audit the frozen lock and scan the built images at implementation. The unused Ajv optional edge needs confirmation through `npm ci` and a Zod form smoke test. If pins or the upstream component registry change materially, return for approval.
- **Multi-tab browser support** — Web Locks prevent concurrent rotation in supporting browsers. Other browsers retain in-tab coordination and can still see token reuse if two tabs refresh together. Document that fallback and keep sign-out deterministic.
- **HTTPS ingress** — Actual deployed host, origin, trusted TLS termination and secure cookie acceptance need a disposable production-style smoke. Granian remains configured as it is. Domain values are operator-supplied.
- **Offset pagination and response gaps** — Category updates between pages can shift items. Invalidate collection queries after mutations. Keep the runtime error parser as the authority while the API documentation follow-up is deferred.
- **Visual and size budgets** — Verify glass visually on platform browsers and measure chart and font costs in the approved build. Treat the proposed budgets as gates and resolve any required adjustment before closure.
